# Svara v0.7.0

This release repairs dictation session handling, microphone recovery and settings,
adds live preview captions and two visualizers, and refreshes the website demo.

## Desktop improvements

- Keep each recording's formatting context and prevent overlapping finalization.
- Synchronize streamed text with stop/cancel; cancel obsolete stop timers.
- Recover cleanly from microphone failures and explain unavailable input devices.
- Show actual partial transcripts in preview mode; clear obsolete recovery audio.
- Add Orbit and Ribbon visualizers, an Appearance settings section and reduced motion.
- Fix dropdown values when multiple desktop windows use different Tk interpreters.
- Validate malformed configuration values without discarding valid preferences.
- Make setup failures actionable and preserve packaged diagnostic logs and exit codes.

## Website

- Add playable dictation examples with pause, resume, replay and progress.
- Improve mobile layout, keyboard access, reduced motion and canvas cleanup.
- Upgrade Next.js and React; the locked dependency audit reports zero vulnerabilities.
- Fix GitHub Pages asset paths and add server/static builds to CI.

## Download and verification

Download `Svara-0.7.0.exe` for Windows 10/11. The single-file download is approximately
111 MB. CPU inference is included; NVIDIA acceleration uses the existing optional
runtime download. The in-app updater offers the new version from the Latest release.
`SHA256SUMS.txt` contains the executable's SHA-256 checksum.

Validation: 547 Windows tests pass, including synthetic-speech streaming and desktop
UI regressions. The built executable's portable doctor passes with the cached
`base.en` model. Both website build modes pass. The previously installed app was
left running; interactive dictation in this packaged executable was not retested.

The CPU benchmark still misses the project's latency budgets: approximately 648 ms
to first word and 782 ms partial p95, with RTF 0.116 and 8.33% WER on three bundled
clips. This measurement used the pre-release worktree while packaging was running;
it is not a speedup claim. GPU throughput and optional local-LLM quality were not
benchmarked. See `AUDIT.md` for findings and remaining limitations.
